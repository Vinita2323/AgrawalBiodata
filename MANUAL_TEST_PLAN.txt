0. BEFORE YOU START
================================================================================

0.1  START THE BACKEND
     Open a terminal:
         cd C:\Users\admin\Desktop\appzeto-2\agarwal\backend
         npm run dev
     Expect: "MongoDB Connected: ac-kkc0uua-shard-00-00.sgtssky.mongodb.net"
             "Server running in development mode on port 5000"
     If the port is busy, close whatever is on 5000 and retry.

0.2  START THE FRONTEND
     A second terminal:
         cd C:\Users\admin\Desktop\appzeto-2\agarwal\frontend
         npm run dev
     Open the URL it prints (normally http://localhost:5173).

0.3  HOW TO GET THE OTP  <-- READ THIS, YOU WILL NEED IT CONSTANTLY
     No SMS is sent in development. The OTP screen does NOT show the code.
     To read it:
         1. Press F12 to open DevTools -> Network tab
         2. Enter the mobile number and press Send OTP
         3. Click the "send-otp" request -> Response tab
         4. Copy the 6 digits from  data.devOtp
     (The one exception is Settings > Account > change mobile, which does
      print the code on screen as "(dev: 123456)".)

0.4  OTP COOLDOWN
     There is a 30-second cooldown between OTP requests to the same number.
     If "devOtp" is missing from the response, you asked too soon - wait 30s.

0.5  TEST NUMBERS
     Use 10-digit numbers you will recognise later, e.g.
         PARENT   9000000001   (will run two children's profiles)
         BRIDE    9000000002   (a separate family)
         GROOM    9000000003   (a separate family)
     Write down which is which - you will switch between them a lot.

0.6  RESET BETWEEN RUNS
     To sign out fully: Profile tab > Settings > Logout.
     For a hard reset in the browser: F12 > Application > Local Storage >
     right-click the site > Clear. Then reload.

4. SEPARATION BETWEEN PROFILES  ***MOST IMPORTANT SECTION***
================================================================================
This is the whole point of the feature. Nothing belonging to one child may
appear under the other.

SETUP: create the BRIDE account (9000000002) with a female profile, and the
GROOM account (9000000003) with a male profile. Fill in city/phone/address
on both so there is something to mask. You now have 3 browsers/accounts:
PARENT (son + daughter), BRIDE, GROOM.
TIP: use a normal window for PARENT and an incognito window for the others,
so you do not have to keep logging in and out.

4.1  As GROOM, find the PARENT's DAUGHTER in Matches or Search and send an
     Interest to her.

4.2  As BRIDE, find the PARENT's SON and send an Interest to him.

4.3  Back on PARENT, switch to the SON, open the Interests tab.
     [ ] You see ONLY the BRIDE's interest.
     [ ] The GROOM's interest (meant for the daughter) is NOT here.

4.4  Switch to the DAUGHTER, open Interests.
     [ ] You see ONLY the GROOM's interest.
     [ ] The BRIDE's interest is NOT here.

4.5  *** PRIVACY CHECK - THE SERIOUS ONE ***
     As the SON, accept the BRIDE's interest.
     Then open the BRIDE's full profile while still acting as the SON.
     [ ] Her phone number and address are FULLY VISIBLE (you are connected).

4.6  Now switch to the DAUGHTER and open the SAME bride's profile.
     [ ] Her phone number is MASKED (e.g. 98290XXXXX).
     [ ] Her address is hidden / "available on connection".
     [ ] The daughter must NOT inherit the son's connection.
     If the daughter can see the full number here, STOP and report it -
     that is a privacy leak.

4.7  Messaging. As the SON (now connected to the BRIDE), open Chat and send
     her a message.
     [ ] The thread appears in the son's Messages tab.

4.8  Switch to the DAUGHTER, open Messages.
     [ ] Her inbox is EMPTY. The son's conversation is not listed.
     [ ] The unread badge does not count the son's messages.

4.9  Shortlist a candidate while acting as the SON.
     [ ] It appears in the son's shortlist.
     [ ] Switch to the DAUGHTER - her shortlist does NOT contain it.
     [ ] Remove it from the son's shortlist - the daughter's list is
         unaffected.

4.10 Notifications. With interests/messages arriving for both children:
     [ ] As the SON, the feed shows only the son's activity.
     [ ] As the DAUGHTER, only hers.

4.11 Matches. Acting as the SON:
     [ ] The PARENT's own DAUGHTER never appears in his matches or search
         results. (Siblings must never be matched to each other.)
